<details>
<summary>Also in the box: rules you can read, AI only if you want it, Answer Later, History, Send later, one Undo</summary>

- **Rules you can read.** Every decision is a rule under Settings › Rules that you can change or revoke. Moving a message yourself teaches the rule that filed it.
- **AI only if you want it.** Standalone Desktop uses your own Anthropic, OpenAI or OpenCode Go key, or a local model through Ollama. Cloud uses its built-in AI and your plan credits; a self-hosted server uses the provider its operator configures. Suggestions and drafts are optional in each mode. Automatic asking and filing are off until enabled; sensitive mail is not filed automatically. Mail containing one-time codes or other authentication material is not sent to a model.
- **Impersonations go to Spam.** A waiting message that presents itself as a company it cannot be from goes to Spam on its own, without AI and without a rule, and stays in ohmail's own Spam. The Screener lists each one with its reason and Put back. Messages with a code in them stay where you see them. You can switch it off.
- **Answer Later, Park and Resurface.** Queue the mail you owe a reply and answer it one at a time in the Reply Run. Or put mail away until the day it should come back.
- **History.** Every message you own, newest first, with the months and years on the side to jump anywhere.
- **Spam.** What you mark as spam goes to your provider's own Junk folder. ohmail deletes nothing on its own.
- **Lists.** When a confirmed list offers one-click unsubscribe, screening it out can send the request. Turn it off with **Unsubscribe when I screen out or mark spam** in Settings. A sent unsubscribe request cannot be undone.
- **Calendar invites** as an event card, **Send later**, **Send + Done** and **Undo** (<kbd>z</kbd>) for filing actions.
- **Tracking pixels.** Recognized tracking pixels are blocked by default. You can turn blocking off; then they load with pictures.
- **Your system's mail app.** ohmail can be your default mail app, so a `mailto:` link opens a new message, already filled in.
- **English and German**, throughout. The [changelog](CHANGELOG.md) is the full list.

</details>

ohmail also has an ohmarchy look, after [Omarchy](https://omarchy.org). On Linux the app starts in it, and on Omarchy it follows your theme.

### Run the server yourself

This quickstart uses the released images: 1.0 today, and 2.0 once that release is published.

```bash
git clone https://github.com/trafficflowhq/ohmail.git
cd ohmail/deploy/selfhost
cp .env.example .env      # fill in the required values; the file explains each
docker compose up -d
docker compose logs -f api # follow until the first-run setup is ready
```

Open your configured site and complete setup using the first-run information in the API log. On a server with a public domain, also set `OHMAIL_BIND=0.0.0.0` in `.env`. There are prebuilt images for amd64 and arm64. The [self-hosting guide](docs/self-host/README.md) takes you from an empty VPS to backups. [ohmail.app](https://ohmail.app) runs the same server source.

## How ohmail organizes inside your mailbox

The folders ohmail creates are a small, frozen set:

```
Inbox                    mail from people you've said yes to
Junk                     your provider's own. Your spam verdicts file into it
Sent                     your replies, left where your provider already keeps them
ohmail/
├── Screener             new senders wait here until you decide where they go
├── News                 newsletters and things you read when you have a minute
├── Receipts             receipts, confirmations, orders
├── Screened             senders you keep, but out of the Inbox
├── Quarantine           spam the automatic patterns set aside, held for review
└── _meta                a small bookkeeping folder. Some mail apps show it
```

The desktop app, ohmail Cloud and a server you run share no database. The mailbox carries your settings (senders screened in, rules and which ones you removed, notification choices, away reply, signature and tag names) as one small message of versioned JSON in `ohmail/_meta`, in a [published format](docs/organizer-profile.md). Connect the same mailbox from another of them, and ohmail finds those settings and asks before using them. Triage piles, Resurface timers, learned patterns, tag assignments, notes and snippets stay where they were made. [How it works](docs/how-it-works.md) has the rest.

## Privacy

The apps send no usage telemetry. Standalone Desktop processes mail and keeps a working copy on your computer; when signed in to Cloud, Cloud organizes mail and keeps a server copy while Desktop keeps a working copy too. ohmail Cloud keeps one record of its own about connecting a mailbox, described at [ohmail.app/privacy](https://ohmail.app/privacy). A server you run and the desktop app keep none. [What the app talks to](docs/how-it-works.md#where-your-mail-is-and-what-the-app-talks-to) lists every connection.

## Contribute

Read [CONTRIBUTING.md](CONTRIBUTING.md) first. Every change is a pull request with a DCO sign-off (`git commit -s`) and a `changelog.d/` entry. `packages/app` and `packages/ui` hold the shared client interface. `apps/webapp` hosts it on the web, and `apps/desktop` hosts it on the desktop with the mail engine in `apps/sidecar`. `apps/mobile` is the phone app. `packages/organizer` holds the organizer. `apps/server` and `apps/worker` run the server stack, with Docker Compose files in `deploy/selfhost`. [Build from source](docs/install.md#build-the-desktop-app-yourself).

Bugs and ideas go to [GitHub issues](https://github.com/trafficflowhq/ohmail/issues). Vulnerabilities go the way [SECURITY.md](SECURITY.md) describes, not into a public issue.
